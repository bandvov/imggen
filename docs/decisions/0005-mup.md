# 0005: muP (maximal-update parametrization)

**Status:** accepted (roadmap step 5)

## Decisions
- `imggen/mup.py`: three parameter roles (`ParamRole.INPUT`, `HIDDEN`, `OUTPUT`), assigned by
  `classify(model)` from each parameter's known structural position (not a shape heuristic), plus
  `FIXED` for biases, norm scales and the additive `mod_table` / `final_table` tables.
  `classify` raises if any parameter is left unassigned, so a new layer kind must be given a role
  explicitly rather than silently falling through.
- **Init:** INPUT and HIDDEN share the same `1/sqrt(fan_in)` std (standard init — muP does not
  change it); OUTPUT gets the extra `1/fan_in` factor prescribed by the Adam column of the muP
  paper's table. FIXED params are left at their construction default (zero for biases, ones for
  norm scales).
- **The adaLN-Zero set stays zero regardless of role**: shared modulation, cross-attention output,
  the head. That's an architectural choice from step 3 (identity at init), independent of muP;
  `MuP.init_` forces zero for that set and applies the role-based init to everything else,
  MoE included (`fc1_weight`/`fc2_weight` = HIDDEN, `router.weight` = OUTPUT since its fan-out,
  the expert count, is fixed).
- **LR:** `lr_multiplier(role, width_mult)` is `1` for INPUT/FIXED and `1/width_mult` for
  HIDDEN/OUTPUT, `width_mult = width / base_width`. `MuP.param_groups(model, lr, weight_decay)`
  builds Adam-ready groups; weight decay is applied only to HIDDEN/OUTPUT weight matrices.
- **One global width_mult**, not per-layer. Every "hidden" dimension in this architecture
  (`ffn_hidden`, `expert_hidden`) is a fixed proportion of `width` by construction (`mlp_ratio`,
  the MoE hidden-size formula), so the model-level `width/base_width` ratio is correct for all of
  them. A future dimension that scales independently of `width` would need its own ratio.
- **Attention logit scale is untouched.** muP's usual 1/d correction (instead of 1/sqrt(d)) is
  only needed when `head_dim` itself scales with width. This project fixes `head_dim` across the
  whole size ladder (ADR 0002) and only adds heads, so the existing `1/sqrt(head_dim)` softmax
  scale already satisfies muP; verified by test.
- `BackboneConfig.mup` (`enabled`, `base_width`), disabled by default. `DiT.init_weights` takes an
  optional `parametrization`; `DiT.__init__` builds a `MuP` from `cfg.mup` automatically. The
  **default (disabled) path is unchanged**: same Xavier init, same call sequence, verified against
  the step-3/4 test suite (184/184 pass unmodified).
- `activation_rms_by_width` + `scripts/mup_check.py`: a block's self-attention output magnitude
  at init, swept across widths. Manual run (base_width=384, depth=4, widths 128–3072): muP stays
  in 0.35–0.43, standard drifts from 0.34 to 0.56. This is a coarse diagnostic (one hook, one
  seed, at init only) meant for quick sanity checks — the rigorous version (several seeds, several
  layers, real optimizer steps, a numeric pass/fail tolerance) is roadmap step 9, not this file.

## Not done / follow-ups
- **Depth transfer is out of scope here.** muP's guarantee is about width; the plan (see the
  original roadmap) already treats depth transfer as needing separate verification. Nothing in
  this step assumes it.
- **The step-9/10 coordinate and transfer checks are still open**: the real test is whether a
  learning rate tuned at `proxy` width stays optimal at `xl`/`4xl`, over real training — that needs
  the training loop (step 7) first.
- **Init variance tests are statistical** (sampled std vs. theoretical std, `rel=0.15–0.25`
  tolerance on a single draw). They're not exact-equality tests; a bad seed could in principle
  flake, though none did across the runs used to write this.
- **MoE + muP interaction is untested beyond parameter coverage and init-variance checks** — no
  training run combining both yet.
